打开 **Model Catalog（模型目录）**选择模型。搜索与分类筛选共同生效，不区分大小写，
每个搜索词都必须匹配模型元数据。**Clear filters** 同时清空两种筛选。

## 一条流程，两种决策方式

| 模式 | 决策规则 |
| --- | --- |
| **Manual** | 根据目标证据、机制覆盖和公开的目标取舍规则比较适用的提供方 / 缓存组合，最后用较少的加速器打破平局；不调用 LLM。 |
| **Agentic** | 根据目标、负载和可用证据比较经过校验的候选；显式选择的 AI 提供方可以提出候选并排序，回退情况会明确标注。 |

两者共用 **部署目标 → 生成 / 比较方案 → 审阅与编辑 → 部署与观察**。
已有部署、兼容 API 和历史计划不会被删除。

“启用更多机制”不代表“参数全部拉满”，也不代表性能最好。互不兼容的提供方方案作为备选展示，
不会被悄悄叠加。缺少前置条件证据的机制保持 **unknown（未知）**。

## 选择目标

1. 选择模型和就绪的 **Cluster（集群）**。Lens 自动生成部署名称，
   展开 **Name and description（名称与描述）**可修改。
2. 选择包含就绪模型的 **Model cache storage（模型缓存存储）**。当前新流程的两种模式都需要已注册的模型缓存。
3. 选择 **Manual** 或 **Agentic**，点击 **Continue to deployment goals（继续配置部署目标）**。

模型缺失时，使用 **Manage model cache（管理模型缓存）**下载。页面打开期间会刷新缓存状态。
参阅[模型缓存](/user-guide/model-cache)和[存储](/user-guide/storage)。

初始上下文长度使用模型卡片的准确 `contextLength`，仅缺失时使用 `4096`。
支持范围为 `256` 到 `1048576`，不会静默缩短。运行镜像来自目标硬件 profile。
副本数、TP 和运行参数在生成后编辑，不再作为初始部署输入。

## 填写需求

两种模式均使用一张简短表单：确认 **Workload（负载）**、**Optimize for（优化目标）**，
以及请求是否共享较长的提示词或文档。默认使用 **General chat（通用对话）**、
**More throughput（更多吞吐）**和 **Do not assume shared content（不假定共享内容）**。
这些是可修改的规划假设，不是已观测流量。明确选择共享内容后，才考虑依赖复用的优化。

**Advanced settings（高级设置）**默认折叠。建议请求大小为 1024 个输入 token 和
256 个输出 token；模型上下文较小时会缩减以适配，但不会修改运行时上下文。
清空 token 字段表示未指定；恢复已有计划时保留原始值，包括未知证据。
负载和延迟目标可选，不会编造 SLO。资源预算默认使用当前空闲容量，优化控制默认 Automatic。
硬件清单和运行时选择由后端处理，不要求用户填写硬件表单。

Manual 点击 **Generate plan and topology（生成方案与拓扑）**，不调用 LLM。
Agentic 点击 **Compare deployment plans（比较部署方案）**，可选 **AI provider（AI 提供方）**。
**Built-in planner（内置规划器）**不调用外部 AI。高级搜索预算默认保留三个候选
（范围 1–10），超时 60 分钟（范围 1–180），默认不启用部署实测。

后端强制执行加速器上限和必须 / 禁止的机制。实际空闲资源始终优先。
必须启用的机制缺少前置条件、要求的组合不兼容或资源不足时会明确失败。
配置能放进显存不代表已经满足延迟目标。

Manual 浏览器流程最多保留 10 个方案 / 缓存备选用于源码检查（Agentic 默认保留三个）。
Manual 将原生 CPU KV 缓存与基线、精确路由、P/D 的组合，以及独立分层缓存方案纳入比较。
这些是规划候选，不代表选中源码版本已经支持组合。CPU 缓存每个服务副本最多 8 GiB，
所有副本合计不超过已发现空闲主机内存的 25%，包含 P/D 两类角色；内存未知时不自动授权卸载。
源码渲染器检查连接器、相同运行镜像、固定版本和放置条件后，才将计划缓存标为启用。
存在模型 / 显存容量估算时，序列数也受其约束。

在目标证据与机制覆盖之后，吞吐优先选择 P/D，其次精确路由；低延迟优先精确路由；
成本优先较少加速器；可靠性优先多个服务副本。仍然相同时选择较少加速器。
选择说明和备选方案公开这一默认规则，不代表实测吞吐或延迟结论。不支持的组合不会被悄悄叠加。

按负载规划目前使用 AIC 原生推荐，只接受并发数或请求率之一。
找不到兼容的负载预测时会报错，不会静默改成无负载约束的估算。

## 审阅与编辑

- 默认进入 **Overview（概览）**。生成 YAML 前展示计划工作负载；
  生成后根据准确的资源清单解析关系。
- **Configuration basis（配置依据）**展示所有机制决策和原因。拓扑下方概述已启用的优化；
  **View all decisions（查看全部决策）**打开完整清单，避免挤占默认视图。
- **3D explorer（三维浏览器）**展示路由 / 模型、服务工作负载和支撑资源层。
  拖动旋转，右键拖动平移，滚轮或缩放按钮调整大小。
  **Focus selected（聚焦选中组件）**居中选中对象，**Reset view（重置视角）**恢复全局视图。
  这些是逻辑层，不是实际物理放置。
- **Overview** 与 **3D explorer** 共用 **Component inspector（组件检查器）**，
  有服务组件时默认选中。点击 **Edit component（编辑组件）**修改当前值；
  选择节点或调整视角不会修改配置。
- 生成资源后可以查看 **YAML**，或点击 **Download YAML（下载 YAML）**。

拓扑编辑展示加速器增量和硬预算影响。侧栏还支持上下文长度、显存利用率、
序列数和批处理 token 上限。运行参数修改适用于所有服务角色，拓扑修改只作用于选中的
Prefill 或 Decode 角色。**Cancel（取消）**放弃待提交修改。
二维和三维切换会保留选中对象和待提交输入。
更换候选或审批前，必须应用或取消当前组件编辑。
生成后，规划活动和 Manual 备选方案默认折叠。
**Ready to deploy?（准备部署）**说明下一步操作；技术检查可以展开，警告始终可见。

**Apply revision（应用修订）**进行实时校验，创建关联原方案的新运行，并使旧 YAML
检查和性能证据失效。失败的修改不会覆盖原方案。必须重新生成资源才能审批。
此处 YAML 为只读，避免无法映射的原始编辑让图形继续显示旧配置。

## 生成、检查与部署

1. Manual 规划后自动生成并检查 YAML；失败重试、更换候选或编辑后，使用
   **Generate and check YAML（生成并检查 YAML）**。Agentic 仍需显式启动此步骤。
   Lens 复用固定源码版本的渲染器，
   检查资源与选中配置的一致性。Manual 只在固定源码已经声明运行参数时，自动补齐前缀缓存和分块预填充。
   一键生成逐项检查保留候选的固定源码，列出被排除方案及原因，并按公开排序选择首个通过的组合。
   全部失败时保留推荐方案、显示失败原因并禁止部署。用户显式选择的候选不会被悄悄替换。
2. 审阅警告、依赖和待检查项。渲染不会安装资源；集群准入、运行就绪和负载性能仍待验证。
3. 点击 **Confirm configuration review（确认配置审阅）**，再点击
   **Approve and deploy reviewed version（审批并部署已审阅版本）**。
   审批会刷新容量，并通过共享部署生命周期提交已审阅清单。
4. 到 **Deployments（部署）**观察就绪状态和失败原因，参阅[管理部署](/user-guide/deployments)。

命名空间绑定、已注册存储挂载等部署时适配仍遵循现有 Deploy 契约。
规划检查通过不保证集群准入或启动成功。

## 证据与受控实测

界面区分**推荐方案**、**性能预测**、已测候选，以及**指定负载和预算内已验证的最佳候选**。
仅出现在实测排名中不代表该方案是第一名，任何结果都不宣称全局最优。

在 Agentic 计划中启用后，实测仍需单独确认，并明确固定负载、候选、资源 / 时间 /
运行次数预算及重复次数。实测复用现有受限的 Deploy/Evaluate 执行器，清理自身创建的部署，
不会自动修改已有部署。中断的实测保留记录，供显式清理。

新流程的运行与修订会随规划快照持久化。刷新可恢复已保存的计划；集群会话过期时，
必须先恢复有效会话再继续操作。修改需求会生成另一个计划。

当前目录没有覆盖全部优化及任意组合。自动扩缩容、投机解码和缺少源码证据的机制标为未知，
不会伪造或直接启用。最终部署仍需真实集群与负载实测验收。
